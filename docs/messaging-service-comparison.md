# メッセージサービスの選定

従業員への配信手段を、コスト・到達性・従業員の使いやすさで比較しました。
（価格は 2026 年 8 月時点の公開情報。断りのない限り税別・年額契約ベース）

## 結論

| 状況 | 推奨 | 追加コスト |
| --- | --- | --- |
| **既存の業務アカウントがなく、現場・外勤スタッフ中心** | **アプリ通知（Web Push / PWA）** | **0 円**（人数無制限） |
| 既存の業務アカウントがなく、PC 中心のデスクワーク | Slack フリープラン | 0 円 |
| Microsoft 365 を契約済み | Microsoft Teams | 0 円 |
| Google Workspace を契約済み | Google Chat | 0 円 |
| 30 名以下で、LINE と同じ操作感を優先したい | LINE WORKS フリープラン | 0 円 |

本アプリはプロバイダを差し替えられる構成のため、`.env` の設定と従業員ごとのサービス指定で切り替えられます。
デスク組と現場組で別のサービスを使う、といった混在も可能です。

## アプリ通知（Web Push / PWA）を推奨する理由

現場・外勤のスタッフに、既存の業務アカウントがない前提では、**導入時の摩擦がそのまま「連絡が届かない人」の数になります。**
アプリ通知は、この摩擦が最も小さい選択肢です。

**従業員がやること**（初回のみ）

1. 配布された自分専用の URL を開く
2. 「ホーム画面に追加」
3. 「通知を有効にする」を押す

以降は通知をタップ → 内容を確認 → 「確認しました」で完了します。
**ID もパスワードも作りません。**メールアドレスも不要です。本人の識別は URL に含まれる推測困難なトークンで行います。

他の選択肢と比べると、Slack や Teams は「メールアドレスを用意 → 招待メールを受信 → アカウント作成 → アプリをインストール → ログイン」という手順が必要で、会社メールを持たない現場スタッフがいると、そこで止まります。

加えて、

- **人数が増えても費用は 0 円。** 外部サービスの人数上限（LINE WORKS の 30 名など）も、通数課金もありません。
- **退職時はトークンを無効化するだけ。** 外部サービスの管理画面を行き来する必要がありません。
- **サービス提供者の都合に左右されません。** 料金改定やプラン変更の影響を受けません。

### 唯一の弱点：iOS の「ホーム画面に追加」

**iPhone / iPad では、Safari で「ホーム画面に追加」した場合のみ通知が届きます。** Safari のタブで開いたままでは通知を受け取れません。これは最新の iOS 26 でも変わっていません。

本アプリでは、この弱点を次の 2 つで埋めています。

1. **iOS では自動的に追加手順を案内する** — 端末を判定し、「ホーム画面に追加」の手順を画面に表示します。
2. **設定が済んでいない従業員を管理画面に表示する** — 端末が未登録の従業員はダッシュボードに警告として並び、従業員画面には「未設定」バッジと案内用 URL が出ます。全員の設定が完了するまで追跡できます。

さらに、レベル高の連絡には従来どおり電話連絡の記録が必須のため、**通知が届かなかった場合でも電話で拾える**設計になっています。

> 到達性をさらに高めたい場合は、レベル高の連絡だけ SMS（1 通 3〜10 円程度）を併用する構成も考えられます。**現時点では未実装です。**

## 各候補の評価

### Slack（フリープラン）

**費用 0 円、API の品質は最上位。** Block Kit のボタンで確認を受け取れ、人数制限もありません。
フリープランの制限（メッセージ履歴 90 日、アプリ連携 10 個まで）は、本アプリが連絡内容を自前の DB に保存し、使用するアプリも 1 個であるため実害になりません。

**PC 中心のデスクワークであれば有力な選択肢です。** 一方、現場スタッフには全員分のメールアドレス準備とアカウント作成が必要になり、導入の負担が大きくなります。

### Discord

**費用は 0 円ですが、業務連絡には推奨しません。**

最大の問題は到達性です。Bot から DM を送るには、対象者が「サーバーメンバーからの DM を許可」する設定にしている必要があり、**拒否設定の人には送信そのものが失敗します。** 従業員が意図せず設定を変更しただけで連絡が届かなくなるのは、この用途では致命的です。

加えてアカウントは従業員個人のもので、退職時にできるのはサーバーからの退出のみです。監査ログなどの管理機能もありません。

### Microsoft Teams

**すでに Microsoft 365 を契約しているなら追加費用 0 円で、最有力の選択肢になります。** Adaptive Cards のボタンで確認を受け取れます。
単体契約の場合は Teams Essentials が 599 円/人/月です。（本アプリには未実装です。必要であれば Google Chat と同様の構成で追加できます）

### Telegram

**完全無料で通数制限もなく、Bot API の品質は Slack 級です。** ただし国内の利用者が少なく、電話番号が必須で、アカウントは個人のものになります。

### Chatwork

**フリープランは 100 ユーザーまで無料**（履歴 40 日）で、国内の中小企業に普及しています。
ただし **API に対話ボタンの仕組みがないため**、確認はメッセージ内のリンクを開く形になります。本アプリの Web 確認画面はすべてのサービスで共通して使えるため動作はしますが、ワンタップでの確認はできません。

### LINE 公式アカウント

**この用途では最もコストが読みにくい選択肢です。**

1. **通数課金と相性が悪い** — 本アプリは「初回配信 + 未確認者へのリマインド最大 3 回」を送るため、1 件の連絡で 1 人あたり最大 4 通が発生します。無料枠は 200 通/月で、ライトプラン 5,000 円/月（5,000 通）が実質的な下限です。
2. **個人アカウントに業務連絡を送ることになる** — 退職時の連絡遮断、私物端末の扱い、勤務時間外の通知など、労務上の整理が別途必要です。

### LINE WORKS

個人の LINE とは別の、**会社が管理するアカウントを使うサービス**です。通数課金はなく、フリープランは 30 名まで 0 円。
LINE と同じ操作感のため、現場スタッフの教育コストが最小という強みがあります。

**31 名以上になると 540 円/人/月**（30 名で月 16,200 円）が発生するため、人数が増える見込みがあるならアプリ通知の方が有利です。

## 「開封済み」の扱いについて

**どのサービスも、メッセージの既読状態を API で取得できません。** そのため本アプリでは次のように記録しています。

- **開封** … 従業員が確認画面を開いた時点
- **確認** … 従業員が「確認しました」を押した時点（通知上のボタン／チャットのボタン／確認画面のいずれでも可）

チャットや通知のボタンを押した場合は、開封と確認が同時に記録されます。
「通知は見たが何も操作していない」状態は、どの手段を使っても検知できません。運用上は「確認」の押下をもって連絡到達の記録とし、レベル高の連絡では加えて電話連絡を行う設計にしています。
