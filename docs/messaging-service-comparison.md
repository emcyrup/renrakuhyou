# メッセージサービスの選定

従業員への配信に使うサービスを、コストと使い勝手の観点で比較しました。
（価格は 2026 年 8 月時点の公開情報。いずれも税別・年額契約ベース）

## 結論

| 状況 | 推奨 | 追加コスト |
| --- | --- | --- |
| すでに Google Workspace を契約している | **Google Chat** | **0 円**（既存契約の範囲内） |
| Workspace を使っていない／現場スタッフ中心・30 名以下 | **LINE WORKS フリープラン** | **0 円**（30 ユーザーまで） |
| 上記が使えず、従業員の個人 LINE に送るしかない | LINE 公式アカウント | 月 5,000 円〜（通数課金） |

本アプリは 3 サービスすべてに対応済みで、`.env` の設定だけで切り替えられます。
まずは `mock` プロバイダで運用フローを固め、サービスは後から決めても問題ありません。

## 比較表

| | Google Chat | LINE WORKS | LINE 公式アカウント |
| --- | --- | --- | --- |
| 月額 | Workspace 契約に含まれる（Business Starter で 800 円/人/月） | フリー: 0 円（30 名まで）／スタンダード: 540 円/人/月 | 無料枠 200 通/月、ライト 5,000 円/月（5,000 通）、スタンダード 15,000 円/月（30,000 通）＋従量 |
| メッセージ通数の課金 | なし | なし | **あり（配信数 × 人数で加算）** |
| 従業員のアカウント | 会社アカウント | 会社アカウント | **従業員個人の LINE** |
| 確認ボタン（対話操作） | カードのボタン → Webhook | ボタンテンプレート → postback | テンプレート → postback |
| Bot からの個別 DM | 可 | 可 | 可（プッシュメッセージ＝課金対象） |
| 既読の API 取得 | 不可 | 不可 | 不可 |
| 導入の手間 | GCP プロジェクト + サービスアカウント | Developer Console で Bot 登録 | LINE Developers で Messaging API チャネル作成 |

## コスト試算（従業員 30 名 / 連絡 20 件/月）

未確認者へのリマインドを含め、月あたりのメッセージ数はおよそ 600〜750 通になります。

- **Google Chat**: 追加 0 円。Workspace 未契約から始める場合でも 800 円/人/月 × 30 名 = 24,000 円/月ですが、メールやカレンダーも含む全社基盤の費用です。
- **LINE WORKS フリー**: 0 円。31 名以上になった時点でスタンダード 540 円/人/月 = 16,200 円/月。
- **LINE 公式アカウント**: 無料枠 200 通では足りず、ライトプラン 5,000 円/月（5,000 通）が必要。連絡頻度が上がるとスタンダード 15,000 円/月へ。**このアプリの用途では最もコストが読みにくい選択肢です。**

## LINE 公式アカウントを推奨しない理由

1. **通数課金と相性が悪い** — 本アプリは「初回配信 + 未確認者へのリマインド最大 3 回」を送るため、1 件の連絡で 1 人あたり最大 4 通が発生します。人数と連絡頻度に比例して課金が増えます。
2. **個人アカウントに業務連絡を送ることになる** — 退職時の連絡遮断、私物端末の扱い、勤務時間外の通知など、労務上の整理が別途必要です。
3. **管理機能が業務向けではない** — 誰が受信できる状態かの棚卸しは、公式アカウントの「友だち」管理で行うことになります。

一方、Google Chat / LINE WORKS はどちらも**会社が管理するアカウント**で、入退社に合わせた停止が管理コンソールで完結し、通数課金もありません。

## 「開封済み」の扱いについて

**どのサービスも、メッセージの既読状態を API で取得できません。** そのため本アプリでは次のように記録しています。

- **開封** … 従業員がメッセージ内のリンクから確認画面を開いた時点
- **確認** … 従業員が「確認しました」ボタンを押した時点（チャット上のボタン／確認画面のどちらでも可）

チャット上のボタンを押した場合は、開封と確認が同時に記録されます。
「トークを開いたが何も操作していない」状態は、どのサービスを使っても検知できません。運用上は「確認」ボタンの押下をもって連絡到達の記録とし、レベル高の連絡では加えて電話連絡を行う設計にしています。
